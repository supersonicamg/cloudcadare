## Run the whole stack locally

> **Changed 2026-11-25: the working target is a cloud Supabase project, not the local stack.** Each client gets their own project; the owner supplies the credentials. Put its URL and keys in `apps/academy/.env.local` and run only `pnpm dev:academy`; you do **not** need `pnpm db:start` or `pnpm mail:sink` (sign-in is email + password, so no mail server is needed; "Confirm email" must be off). The local stack below is optional now (SQL tests, and the e2e suite, whose receipt checks read the local mail sink). Model, per-client checklist and open items: [plan/14-delivery-and-hosting.md](plan/14-delivery-and-hosting.md).

Needs Node 22+ (this machine's default is 20.17; put `~/.local/share/fnm/node-versions/v22.23.5/installation/bin` first on `PATH`, `fnm use` does not stick in the agent shell), pnpm 10 (`corepack enable`), podman (rootless; `systemctl --user start podman.socket`).

```bash
pnpm install
pnpm db:start            # Supabase (db, auth, rest, storage, kong). Applies all migrations in packages/db/supabase/migrations
pnpm mail:sink           # separate terminal: captures app mail such as receipts (logs to /tmp/educore-mail.log)
# apps/academy/.env.local and apps/console/.env.local: copy the keys printed by `pnpm db:start` (see each .env.example)
# one-off SQL: update control.platform_settings set value = '"localhost"' where key = 'base_domain';
pnpm dev:academy         # http://<slug>.localhost:3000
pnpm e2e                 # Playwright against the running stack (needs the mail sink and an academy named "cloudcadre", see below)
```

The e2e tests expect an academy at `cloudcadre.localhost:3000` whose owner is `founder@example.com`. Create it once: sign up on the console, add the user to `control.distributor_members` (SQL in Gotchas), create a key and redeem it with slug `cloudcadre`.

## Decisions and deviations from the plan

- **Delivery model (owner, 2026-11-25):** one cloud Supabase project per client (the plan's "dedicated plane", now the default), app on Vercel first and then the owner's VPS (several light clients per KVM 2/4), no local-Supabase testing. Not yet built: client provisioning script, migration roll-out across projects, e2e against a cloud project. See [plan/14-delivery-and-hosting.md](plan/14-delivery-and-hosting.md) and ADR-16.

- **Package scope `@educore/*`** (plan sketches `@core/*`). Rename with a global replace when the brand is decided.
- **"Just-in-time" workspace packages**: they export `.ts` source and the apps list them in `transpilePackages`. No build step per package.
- **Tailwind via `@tailwindcss/postcss`** (documented route), replacing the template's `@tailwindcss/turbopack` rules. Tailwind 4.3 needs **Node ≥ 20.19**; the machine default (20.17) fails with `ERR_REQUIRE_ESM`. Use Node 22+ (`fnm install 22`). pnpm is pinned to 10.33 (`packageManager`) because pnpm 11 needs Node 22.13+.
- **`next/root-params` is injected per app**: `lib/tenant.ts` in the app reads it; packages never import it (it only type-checks inside an app).
- **Placeholder slug `root`** feeds `generateStaticParams` (Cache Components requires a value). It is a reserved slug, and `resolveHost` refuses to route to it.
- **`export const instant = false`** on `app/[tenant]/layout.tsx`: academies are an unbounded set known only at request time, so the first render per academy blocks on the cached tenant bundle. This is deliberate; keep it on the layout.
- **No `app/layout.tsx`**: the app has two root layouts (`app/[tenant]` and `app/platform`). Everything routable must live under one of them.
- **`new Date()` is banned while prerendering**: the year comes from the cached `getCurrentYear()` and is passed to themes as `brand.year`. Themes must not call `new Date()`/`Math.random()` at render.
- **Schema addition `public.join_tenant(uuid, text)`** (migration `…15_91_membership.sql`, not in the original plan): learner self-signup after OTP (idempotent, honours `tenant_settings.auth.open_signup`, blocked members stay blocked, grants the `student` role). Covered by 3 new smoke assertions. Phone comes from the JWT claim because the bare test image's `auth.users` has no `phone` column.
- **Console is a separate app with Cache Components off** and `dynamic = 'force-dynamic'` on its root layout (otherwise config-dependent pages get prerendered at build). `/start` (redeem) lives in the console for now instead of a separate `apps/start`.
- **Dev fixtures**: with no `SUPABASE_URL` and `NODE_ENV != production`, the tenant loader serves a `demo` fixture tenant (and nothing else). `EDUCORE_FIXTURES=1` forces it. Never set that in production.
- **Migration 17 `public.my_access(tenant)`** returns member id, status, tenant-wide permission keys and the session's `aal` in one call; `lib/dal.ts` turns it into a `Principal`. RLS stays the real enforcement; the DAL only decides what UI and server paths to offer.
- **DAL rules (`apps/academy/lib/dal.ts`)**: pages use `requireAccess` (redirect when signed out, 404 when not allowed); server actions use `requireActionAccess`, which derives the tenant from the Host header, never from the client. Admin data always goes through the **user-scoped** client, so RLS applies; the privileged client is used only for anonymous public reads (`@educore/core/catalog`, explicit tenant filter and explicit columns).
- **Cache tags**: `tenant:{id}:branding` (tenant bundle), `tenant:{id}:catalog` (public course reads). Every admin write that changes public output must call `updateTag` for the right tag.
- **Theme contract** now has `SiteLayout`, `AuthLayout`, `HomePage`, `CatalogPage`, `CoursePage`. DTO types live in `@educore/ui/theme` (themes may not import core). Terminology is hard-coded in `lib/shell.ts` (`TERMS`) until the resolver reads `tenant_settings.terminology`.
- **Typed DB**: `packages/db/src/types.ts` is generated (`pnpm db:types`); regenerate after every migration.
- **Self-enrolment (migration 17, `public.enroll_in_course`).** Not in the original plan. Opens only when the course has `settings.enrolment = 'open'` (admin checkbox "Anyone with an account can enrol for free", off by default) AND no product sells the course. Enrolments still have no client write policy; this function is the only learner door. Paid and admin-granted enrolments will come from the privileged fulfilment path (slice 3).
- **Staff MFA (session 4).** Supabase Auth TOTP (`[auth.mfa.totp]` enabled in `config.toml`). `requireAccess` redirects to `/admin/mfa?next=` when the member holds a sensitive permission but the session is aal1 (`/admin/security` first when no factor exists); server actions throw `MfaRequired`. `safeAdminNext` (`lib/admin-next.ts`) limits `next` to `/admin…`. Menus use `holds()` (permission regardless of aal) so the item shows and the page asks for the code. Sensitive permissions (prices, gateway keys, roles, settings, enrolment, refunds...) all go through this; **`price.manage` and `integration.manage` are sensitive, so checkout admin needs it.**
- **Admin enrol/revoke (migration 18, `grant_enrollment`, `revoke_enrollment`).** Need `enrollment.manage` in the tenant AND `aal2` in the JWT, checked inside the functions regardless of the tenant MFA setting. UI at `/admin/enrolments` (grant by email of someone who has signed in once; list; remove access).
- **Media model for now:** lesson video is a `media_assets` row created from what staff paste (YouTube link, Mux playback id, direct https `.mp4`/`.webm`/`.m3u8`). No uploads. `@educore/core/media` has the pure parsers (`parseVideoSource`), the Mux token signer, and `resolvePlayback` (privileged: it runs only after RLS on `lessons` proved the learner may see the lesson). Signed Mux playback needs `MUX_SIGNING_KEY_ID` and `MUX_SIGNING_PRIVATE_KEY` (see `.env.example`).
- **Lesson types the learner side plays:** `video`, `article` (Markdown in `lessons.body = {format, text}`, rendered by react-markdown, images off), `external_link`. The admin add form only offers those three. `pdf`, `document`, `download`, quiz, test, assignment, live show "not available yet".
- **Progress path:** the player posts to `app/[tenant]/api/progress/route.ts`, which calls `record_lesson_progress` as the user (RLS-scoped client). The route checks `Origin` against `Host` (CSRF) and the database function does the real validation (membership, enrolment, completion rule, 120 s delta cap). Free previews return `{tracked:false}`.

## Gotchas

- **Starting `next dev` on Node 20 poisons the dev cache:** CSS fails with `require() of ES Module ... magic-string`, and it keeps failing on Node 22 until `apps/academy/.next/dev` is deleted.
- **Redis domain map must be written whenever a tenant or domain changes.** When `UPSTASH_REDIS_REST_URL` is set, the map is authoritative and an unwritten host resolves to "unknown". `syncDomainMap` is called after redeem only. Suspend/resume, domain verification and removal must call it too, and a periodic reconcile job should repair drift.
- **Base domain for local dev**: the seed sets `platform_settings.base_domain = yourplatform.app`, and `redeem_license` uses it for the first subdomain. For local work run `update control.platform_settings set value = '"localhost"' where key = 'base_domain';` and set `BASE_DOMAIN=localhost`.
- **First console user**: staff access needs a row in `control.distributor_members`. Bootstrap once with SQL: `insert into control.distributor_members (distributor_id, user_id, role) select id, '<auth user uuid>', 'owner' from control.distributors where kind = 'platform';`
- The `control` schema is never exposed over the Data API; the console reaches it through `CONTROL_DATABASE_URL` (postgres.js, server-only).
- Do not run `pkill -f "next dev"` from the agent shell: the pattern matches the shell's own command line and kills it.
- `playwright install chromium-headless-shell` was needed once (browser build must match `@playwright/test`).
- Local Supabase ports: API 54321, DB 54322 (`postgres`/`postgres`), SMTP sink 54325. `supabase start` needs `DOCKER_HOST` pointing at the podman socket (the `pnpm db:*` scripts set it).
- `PG_PORT=54329 ./packages/db/tests/run_local.sh` leaves a Postgres on localhost:54329 (user/password `postgres`) with smoke-test data; useful as `CONTROL_DATABASE_URL`.
- **Playwright and hidden routes:** Next (Cache Components) keeps previously visited routes mounted but hidden, so `getByText('Saved.')` can match several elements. Use `.filter({ visible: true })` (see `e2e/learn.spec.ts`).
- **e2e MFA:** `e2e/helpers.ts` has `totp(secret)` (RFC 6238) and `resetMfa(email)` (removes factors through the Auth admin API using the keys in `apps/academy/.env.local`), so `e2e/mfa.spec.ts` can enrol the owner again on every run. Each Playwright test gets a fresh browser context, so a test that needs an aal2 session must enrol/verify in the same test.
- **`'use server'` files may only export async functions** (a sync helper such as `safeAdminNext` there breaks the whole file at compile time); keep helpers in `lib/`.
- **e2e sign-in helper reads the code from `>123456<`**, not the first 6-digit number in the mail: a `To:` address such as `learner-828792@…` matched the old regex.
- **Next dev validation noise:** the dev server logs "unstable value `Date.now()`" for every route that reads the session (it comes from JWT verification) and "URL data during prerendering" for `/courses/[slug]`. Pages return 200 and `next build` passes; the root layout has `instant = false`. Not investigated further; revisit when adopting instant navigation.
- Every Bash call prints a harmless "Node.js path is not on your PATH" fnm warning on this machine.
